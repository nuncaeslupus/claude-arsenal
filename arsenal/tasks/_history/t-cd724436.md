Three documentation defects. The first has a code-side root cause.

1. docs/INSTALL.md:144 tells a consumer that `ls .claude/skills` shows "17 skill
   folders" after the walkthrough's own --profile python example. Running
   `init.py --profile python` in a scratch repo produces 18. The root cause is
   upstream of the count: docs/INSTALL.md:82 and init.py:148-149 both describe
   the python section as python-bootstrap, pypi-release, coverage-gaps,
   dep-upgrade, mutmut-report — five skills. pin-check/SKILL.md declares
   `section: python` and sections.json agrees there are six. So pin-check
   installs correctly but is absent from both prose listings, and the verify
   step teaches a consumer to expect the wrong number.

2. ship/SKILL.md:103-104 reads `<!-- ship: adversarial-review=skip -->` from the
   host repo's CLAUDE.md. CLAUDE.md's flag registry at :305-320 states it is
   "the full registry of flags a core skill honors" and lists only
   test-discipline, session-end and github-skill. A live marker is undocumented
   in the document that claims completeness — the mirror image of the six dead
   config keys, which are documented and unread.

3. docs/research/claude-skill-system_v1.17.md has 67 internal links that resolve
   to no anchor — [R-CHUNK-5](#r-chunk-5) and the like, whose targets are marked
   with `<!-- @rule: R-CHUNK-5 -->` HTML comments, which produce no id when
   rendered. Confined to the research archive; every relative link in README.md,
   CLAUDE.md and all of docs/ outside it resolves.

Done means: the python-section listings agree with sections.json, the registry
documents the ship marker, and the archive's self-references resolve.

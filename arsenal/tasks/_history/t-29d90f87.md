Instruction length is a cost paid by every session that loads the file, and
length that does not pay for itself makes the agent do the job worse, not
better. Three specific cases, in descending order of traffic.

1. skill-workshop/SKILL.md states its gate procedure three times: "The two
   passes" (:39-59), then "Operational checklist" items 1-3 (:89-92) restating
   it, then "Before committing" (:244-245) pointing back at it. At 3,195
   on-invocation tokens this is the highest-traffic skill in the repo — the
   pre-edit hook requires it loaded before any skill file is touched. The
   checklist's 5 genuinely new items are diluted by 3 that just re-say "run the
   two passes". Fix: delete items 1-3, fold 4-8 into "The two passes", cut
   "Before committing" to its 2 new bullets.

2. repo-audit/references/issue-taxonomy.md (144 lines, 1,763 tokens) enumerates
   generic bug patterns — mutable default arguments, bare except, is vs ==,
   string-built SQL — at ~3x the density of research-categories.md (46 lines),
   which does the same dispatch job. A competent model checks these unprompted.
   Spelling them out hands a hunt worker a list to pattern-match instead of
   reading code on its own terms. Fix: one open prompt per category at
   research-categories.md's density, keeping the non-generic lines (e.g. "a CVE
   at the version actually pinned").

3. Two of repo-audit/SKILL.md's Gotchas (:90-94, :116-119) condense sections
   output-shape.md already states in full (:85-92, :55-83). Nothing signals the
   fuller decision tree exists, so the short version reads as complete and a
   reader can miss the queue/issue/ledger distinctions. Fix: one line naming the
   reference instead.

While rewriting issue-taxonomy.md, add the group this audit did not have:
simplicity and instruction economy. It found real defects the other eight
missed, including item 1 above.

Done means: each file says its thing once, issue-taxonomy.md prompts judgment
rather than listing patterns, and the resident/on-invocation tiers are smaller
than before.

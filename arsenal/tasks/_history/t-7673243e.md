**Where:** `plugins/core/skills/init/scripts/init.py:791-822, plugins/core/skills/init/assets/bin/statusline_capture.sh`

### Finding
`_register_statusline` only checks the project `.claude/settings.json`; when it has no `statusLine` it writes `statusline_capture.sh` there and the file is committed. Project settings take precedence over `~/.claude/settings.json`, so every contributor's personal status line is replaced in this repo by a capture script, and the docstring's 'a user's existing statusLine is never clobbered' holds only for a project-level one. statusline_capture.sh also has no test.

### Evidence
Read init.py:791-822; grep for statusline_capture.sh across plugins/*/tests and scripts/*_test.sh → no test names it (init_test may cover registration only).

### Suggested direction
Make statusLine registration opt-in, or write it to settings.local.json; add a behaviour test for the script.

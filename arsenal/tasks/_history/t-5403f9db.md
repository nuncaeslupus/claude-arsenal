Issue #375 — found in a consumer (`nuncaeslupus/opos`) that works only from
Claude Code on the web.

`references/claiming-internals.md` admits claim refs accumulate, roughly one per
task ever claimed, and offers one remedy: "prune them from a CLI session
occasionally". That consumer has no CLI session, and its proxy rejects every ref
write — `git push --delete` and the REST `DELETE` both 403 — so the only remedy
the bundle offers can never be run there, and the cost it acknowledges has no
ceiling.

No session-side fix works: the 403 is the proxy, whoever makes the call. The
prune has to happen where a write token already exists — GitHub Actions. The
`sweep-claims` job in `arsenal-queue.yml` already runs on a schedule and already
releases the *label*; it never touched the ref.

Fix: a `prune-claims` command in `queue_hooks.py` that lists refs under the claim
prefix and deletes those whose task is terminal (`done`/`merged`, i.e. archived in
`_history`), planned-then-applied like every other command so `--dry-run` covers
it. Wire it into the scheduled job with `contents: write`, and rewrite the
reference sentence so it no longer prescribes a surface most consumers do not have.

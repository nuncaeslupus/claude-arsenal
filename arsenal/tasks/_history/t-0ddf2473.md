_prune_bundle (init.py:329-348) sweeps claude-arsenal/{bin,scripts,references}/
and unconditionally unlinks every file not in the current bundle. No ownership
marker, no rescue snapshot, one line of output. Its sibling _vendor_skills does
the opposite — it checks .arsenal-vendored and prints "exists and is not
arsenal-vendored — left alone" (:976). Two functions in one file, opposite
safety postures.

Failure scenario: a consumer commits claude-arsenal/bin/my-helper.sh — the
obvious place, since every bundle script lives there and nothing marks the
directory as owned. The next `init.py --silent`, which runs at EVERY session
start, deletes it. No rescue ref, unlike worker_postcheck.sh's
snapshot-before-destroy pattern elsewhere in this same repo.

The docstring misleads on two counts: it says "Only the two upstream-owned
directories are swept" while _PRUNABLE_DIRS has three entries, and "host trees
are never touched" is true only at directory granularity.

Second defect, same function: the loop skips directories entirely (`if not
installed.is_file(): continue`), so a retired file under scripts/lib/ is never
pruned. Latent today — the bundle ships no nested subdirectory — but it is the
stated purpose of the function silently not happening.

Done means: a host-authored file in a swept directory survives an upgrade, and
a retired nested file does not.

### Finding
When the current branch is not arsenal/<id>-<slug>, the script does `git checkout -b $BRANCH $default_ref`; only uncommitted edits ride along. If the session committed its work on its own branch (normal on cloud surfaces) and did not pass --branch, the new branch contains only the task-file archive, yet the PR body says the acceptance gate passed and carries `Closes #N` (the task gate ran on the pre-checkout tree).

### Evidence
Traced order: task gate (L423) runs before branch phase (L681-690); no rev-list/ahead check exists (`grep -n 'ahead\|rev-list' open_task_pr.sh` is empty). Host gate after checkout only catches it if one is configured and sensitive to the change.

### Suggested direction
Before cutting the branch, refuse (or cherry-pick) when HEAD has commits not on the default branch; refuse to commit when the diff is only the archive rename.

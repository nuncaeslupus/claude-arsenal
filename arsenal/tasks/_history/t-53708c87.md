**Severity:** medium · **Confidence:** high · **Category:** release

**Where:** `Makefile:74-94`

### Finding
The manual fallback tags whatever HEAD is; it never checks that HEAD is on origin/main or that CI passed. Run on the bump's feature branch (where .bundle-version already has the new value) it publishes an unmerged commit as the release every consumer fetches, and after a squash merge the tag never points at main.

### Evidence
Read the recipe: checks are remote-tag-exists, monotonic version, local-tag==HEAD; no branch or ancestry test. tag-release.yml requires green CI, this path bypasses it by design but without the main check.

### Suggested direction
Refuse unless HEAD == origin/main (after fetch), and print the CI status of that commit when gh is available.

validate_markdown.py's PLACEHOLDER_TOKEN_RE (:28) matches any <word> and is
applied unconditionally in check_file (:47-49), including inside fenced code
blocks. So it flags the repo's own CLI-usage convention. Run against the skill
that ships it:

  SKILL.md:74  unfilled template token (<target-repo>)
  SKILL.md:74  unfilled template token (<path-to-changed-docs>)
  SKILL.md:81  unfilled template token (<category>)
  output-shape.md:67-68  (<category>, <target-repo>)

All six are intentional placeholders in documented bash usage. A script whose
value is being a trustworthy one-line signal instead makes the agent second-guess
or hand-dismiss its own validator on a routine run — the opposite of what a
deterministic check is for. Target repos are likely to use the same convention.

Done means: the check no longer fires on a documented placeholder. Either drop
PLACEHOLDER_TOKEN_RE and keep TODO/FIXME/TBD/XXX, which are unambiguous, or skip
fenced blocks.

# The validator must not flag the skill that ships it.

  --input-dir plugins/repo-audit/skills/repo-audit --repo-root .

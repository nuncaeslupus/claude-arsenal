Issue #374 — found in a consumer (`nuncaeslupus/opos`) importing one issue.

`AGENTS.md` calls `issue_import.py` "the only sync in the system: one-directional
and **idempotent**". It is not: the task id comes from `new_task_id()`, four
random bytes, so the dry run announces an id that will never exist and a second
`--apply` on the same issue mints a *second* task file for it. Two task files for
one issue is one piece of work dispatched twice, with two claims that cannot
collide because the ids differ — the exact failure the claim ref exists to stop.

Fix: derive the id from the issue's own identity (`html_url`, falling back to the
issue number) instead of from `secrets`, and skip an issue whose derived task file
is already on disk — including in `_history`. Then the dry run tells the truth and
`--apply` twice is a no-op. `create_task.py` keeps its random ids: those are minted
by concurrent agents with no shared identity to derive from.

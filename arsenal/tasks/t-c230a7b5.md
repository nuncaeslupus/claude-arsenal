Design: `docs/design/0003-capability-discovery.md` § 3–4.

A vendored `init.py` cannot see the skills it did not install, so the map has to be
shipped data. This task ships that data and the command that prints it:

- `plugins/core/skills/init/assets/sections.json` — generated, committed manifest of
  every section (name, default, blurb) and every skill (name, description).
- `scripts/sync_sections.py` — generator with `--check`, mirroring `sync_version.py`.
  Fails when a shipped `section:` has no `SECTION_BLURBS` entry (SC4).
- `make sync-sections` / `make sync-sections-check`, wired into CI beside
  `sync-version-check`.
- `init.py --list-sections` (one line per section; skills named for `off` sections
  only) and `--section NAME` (per-skill detail from the manifest). Writes nothing.
- `plugins/core/tests/list_sections_test.sh` covering SC1, SC2, SC5 and the
  manifest-missing fallback.

Bumps `.bundle-version` (minor) with a CHANGELOG entry, like every PR in this stack:
each one changes a file a consumer vendors, so the stacking rule's "only the last PR bumps" does not apply — see `0003-capability-discovery.md` § 9.


## Acceptance gate

```bash
bash plugins/core/tests/list_sections_test.sh
bash plugins/core/tests/skill_sections_test.sh
make sync-sections-check
```

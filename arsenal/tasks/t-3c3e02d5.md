Six skills ship the scaffold string `this-fact-is-false-and-must-not-appear-in-the-skill-body`
as their `negative_control` (bugreport, har, init, queue-add, queue-next, queue-status), so
the loading eval proves nothing about them. skill-workshop's own negative control is a true
statement about the skill. github's names a specific vendor bot (Gemini). repo-audit's eval
prompts are off-target, and one of them belongs to explain-repo.

Done means: each control is a plausible but false claim about that skill, and the eval prompts
are in scope.

Found by the semantic skill-workshop walk over all skills (2026-11-09).

set -e
if grep -l 'this-fact-is-false' plugins/*/skills/*/evals/loading_verification.json; then exit 1; fi

**Severity:** high · **Confidence:** medium · **Category:** correctness

**Where:** `plugins/core/skills/init/scripts/init.py:1416-1455, plugins/skill-workshop/hooks/check_skill_workshop_loaded.sh:66-92, plugins/skill-workshop/hooks/mark_skill_workshop_loaded_from_prompt.sh:24-40`

### Finding
init.py registers check_skill_workshop_loaded.sh as a PreToolUse hook in every consumer's .claude/settings.json, but /init only vendors plugins/core/skills (no skill-workshop, no skill-creator). A cloud/vendored-only session that edits its own .claude/skills/<x>/ file is blocked with 'invoke skill-workshop first', a skill that is not in its listing; the only escape is a user typing the literal text '/skill-workshop', which sets the marker without the skill existing.

### Evidence
Traced: `wanted` list registers the hook unconditionally; `ls plugins/core/skills` has no skill-workshop; _source_skills_dir() is core's skills dir; hook exits 2 for any */.claude/skills/* target without the marker. Not run in a real consumer session.

### Suggested direction
Register the gate only when a skill-workshop/skill-creator skill is actually present (or make the hook allow when neither is installed), and say so in the block message.

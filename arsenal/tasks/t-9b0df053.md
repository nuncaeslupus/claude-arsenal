Two independent ways the dispatch guard stops stopping.

1. A flat top-level used_percentage is ignored. The percentage loop (:241-266)
   reads only data["five_hour"] / data["seven_day"], though top-level `status`
   IS read at :220. Reproduced, same value and threshold:

     {"status":"allowed","used_percentage":97,...}  -> "ok (status='allowed', no
                                                       used_percentage on this
                                                       surface)"          exit 0
     {"five_hour":{"used_percentage":97}}           -> "97% >= 90%"       exit 3

   The message asserts the absence of a field the document contains.

2. The dispatch-round counter (:136-148) is a single-slot {session, count} file
   on a relative path. Two sessions sharing a clone each see session != their own
   and reset to 1, forever — so ARSENAL_MAX_ITERATIONS, documented as the backstop
   that does NOT depend on observable state, never trips for either.

Done means: a percentage over threshold stops the round wherever it appears in
the document, and the round counter survives a second concurrent session.


## Acceptance gate

```bash
# A flat top-level percentage over the stop threshold must stop the round (exit 3).
T=$(mktemp -d); mkdir -p "$T/session"
echo '{"status":"allowed","used_percentage":97,"rateLimitType":"five_hour"}' > "$T/rl.json"
ARSENAL_SESSION_DIR="$T/session" ARSENAL_RATE_LIMITS_FILE="$T/rl.json" \
  bash plugins/core/skills/init/assets/bin/budget_check.sh; rc=$?
rm -rf "$T"
[ "$rc" -eq 3 ] || { echo "flat used_percentage=97 did not stop the round (exit $rc)" >&2; exit 1; }
```

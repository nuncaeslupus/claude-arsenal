### Finding
github_channel.sh maps any HTTP 422 to exit 3 and claim_task.sh prints 'lost' (someone else holds the claim). claim_task falls back to local HEAD when the remote default ref cannot be resolved; an unpushed HEAD makes GitHub answer 422 'Object does not exist', so the task is reported as taken by another session and skipped although no claim ref exists.

### Evidence
Traced: `grep -qi 'already exists\|HTTP 422'` and `[[ code == 422 ]] && return 3`; claim_task `case 3) echo lost`. GitHub returns 422 for both 'Reference already exists' and 'Object does not exist'/invalid ref name.

### Suggested direction
Return 3 only when the body says 'Reference already exists'; treat other 422s as errors (exit 2) with the message shown.

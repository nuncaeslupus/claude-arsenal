Two defects on the path a session actually uses to read the board.

1. The --json branch prints `problems` and returns (:296-316). Everything in
   `warnings` and `notes` is computed before that point and printed only after
   it (:362-363) — duplicate task id, malformed front matter, title collision,
   the board-read-as-stateless note, and the mixed-priority-convention warning.
   A machine caller running `--json --fail-on-problems` therefore never learns
   its board has two tasks sharing an id. JSON is the documented cheap-fetch
   path, so the automated consumer is the blind one.

2. Issue resolution rescans all issues per task: query_status.py:260 and :308
   call issue_for_task.py:55, which loops every issue for each call. That is
   O(tasks x issues) on a session-start path — invisible at 13 tasks, roughly
   40,000 regex calls at the 200-task scale the queue is designed for. The
   single pass state_from_issues already makes over the issues could build the
   dict once.

Done means: a --json caller receives the same warnings a text caller does, and
issue resolution is O(tasks + issues).


## Acceptance gate

```bash
# A duplicate task id must be reported in JSON mode too, not only in text mode.
set -e
T=$(mktemp -d); mkdir -p "$T/tasks"
printf -- '---\nid: t-dupe0001\ntitle: one\n---\n' > "$T/tasks/a.md"
printf -- '---\nid: t-dupe0001\ntitle: two\n---\n' > "$T/tasks/b.md"
out=$(python3 plugins/core/skills/init/assets/scripts/query_status.py \
        --tasks-dir "$T/tasks" --json 2>&1 >/dev/null || true)
rm -rf "$T"
echo "$out" | grep -qi 'duplicate' || { echo "duplicate id not reported in --json mode" >&2; exit 1; }
```

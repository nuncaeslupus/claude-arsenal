gate_run.sh strips $HOME-writable entries from PATH (_under_home, :354-361,
:364-369) so a gate running attacker-influenceable code cannot pick up a
trojaned tool — the RCE-from-data scenario its own docstring names at :30-32.

The re-admit loop (:379-383) then undoes it: it locates each allowed tool with
shutil.which(tool, path=os.environ.get("PATH","")) — the ORIGINAL, un-hardened
PATH — and prepends that tool's whole directory unconditionally, without
re-applying _under_home to the result.

Failure scenario: a gate running `node` or `pnpm` resolves to
~/.nvm/versions/node/v20/bin. That directory is also where every `npm install
-g` shim lands, and anything a dependency's postinstall dropped. It is now
ahead of /usr/bin, so a file named `git`, `curl` or `make` there runs instead of
the system binary — inside the gate.

Done means: the re-admit path applies the same _under_home filter it just used
to strip, or resolves tools against the hardened PATH rather than the original.

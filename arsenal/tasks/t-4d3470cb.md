### Finding
With `queue-automation = true` in arsenal/config.toml and no .github/workflows/arsenal-queue.yml on disk, init --silent writes `false` permanently. A session whose token cannot push workflow files (common: no `workflow` scope) commits config.toml but not the workflow; the next fresh clone's session start then disables queue automation for good and says the user removed it.

### Evidence
Traced the `setting == "true"` and target-missing branch; init --silent runs at every session start per AGENTS.md step 0b. Scenario depends on the two files landing in different commits; not reproduced.

### Suggested direction
Only record the opt-out when git history shows the workflow was committed and then deleted (or ask on a non-silent run); on --silent just warn.

Four unrelated, individually small defects, grouped because each is a few lines.

1. validate.py:611-614 checks two of R-FM-2's four reserved words. The rule
   reserves anthropic, claude, mcp and agent; the validator checks the first two,
   and its failure message enumerates only those, so a skill named `mcp-bridge`
   or `agent-runner` passes while violating the rule the validator exists to
   enforce.

2. queue_hooks.py:316-318 CLOSING_REFERENCE requires whitespace between the
   keyword and #N, so GitHub's own documented `Closes: #42` colon form does not
   match. keyword-guard then fails a PR that would correctly close the issue.

3. query_har.py:255 parses --list-only and never reads it. Listing is already
   the unconditional default, so the flag exists only to be ignored by a caller
   who expects it to mean something.

4. claim_task.sh:94 builds its ref-creation JSON with an unescaped
   printf '{"ref":"%s","sha":"%s"}'. open_task_pr.sh:884 uses json.dumps for the
   equivalent payload and adversarial_review.sh:138 charset-checks the same
   TASK_ID, so the project already knows this value needs guarding. Today's input
   is the agent's own task listing, so the exposure is narrow — but it is the odd
   one out.

Done means: all four fixed, and R-FM-2's message lists what it actually checks.

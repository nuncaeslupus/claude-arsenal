**Severity:** medium · **Confidence:** medium · **Category:** error-handling

**Where:** `plugins/core/skills/init/assets/scripts/arsenal_config.py:35, plugins/core/skills/init/scripts/init.py:16, plugins/core/skills/init/assets/bin/claim_task.sh:63, plugins/core/hooks/detect_surface.sh:63`

### Finding
arsenal_config.py and init.py import tomllib unconditionally and are invoked as bare `python3`. On stock macOS (python3 = 3.9) claim_task.sh's `arsenal_config.py --get claim-prefix 2>/dev/null || true` silently falls back to the default prefix (two machines then claim under different refs), detect_surface.sh silently drops host capability probes, and init.py dies with an ImportError traceback.

### Evidence
grep: no sys.version_info guard anywhere under plugins/core; docs/INSTALL.md:33 lists Python 3.12+ only for skill-workshop scripts; CI macOS leg installs 3.12 via uv so it cannot catch this. Not run on 3.9.

### Suggested direction
Add a one-line version guard with a clear message at the top of the entry scripts, and stop discarding stderr where a config read decides behaviour.

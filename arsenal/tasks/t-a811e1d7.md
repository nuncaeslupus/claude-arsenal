`make queue-doctor` runs `query_status.py` with no `--issues`, so `handled` is empty
and every task file reports `no issue handle`. With an empty `arsenal/tasks/` the job
passed vacuously; the first task file added to this repo turns the dogfood into a
build that cannot go green. Found by adding one.

"I did not ask GitHub" and "GitHub has no handle for this" are different answers and
the script conflates them.

- `query_status.py`: when `--issues` is absent entirely, do not raise the no-handle
  problem — report that handle checking was skipped, and mark rows `handle?` rather
  than `no-handle`. When `--issues` is supplied, behaviour is unchanged.
- `Makefile`: `queue-doctor` fetches the `arsenal:task` issues into a temp file when a
  GitHub channel is available and passes `--issues`, so the check is real where it can
  be and skipped where it cannot.
- CI: give the `queue doctor` job a token so its fetch succeeds — the dogfood is only
  worth running if it can fail.


## Acceptance gate

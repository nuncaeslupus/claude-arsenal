▸Technical solution

▸Architecture overview

P1 makes risk decide who approves. One new pure module, review_policy.py, classifies a PR's files into low|medium|high and maps the tier to an approval requirement from review-preset, [review.tiers], [review.approval] and always-human-paths. pr_audit.py (behind merge_ready.sh) asks it for the requirement and counts what the head actually has: an agent review (existing CLEAR marker or bot review) and human approvals (GitHub APPROVED reviews from non-bot, trusted, non-implementer users on the head SHA). merge_ready.sh --body writes the result as merge-commit trailers, which P2's digest reads. review_sources.py keeps deciding review depth, now from the same tier. /init asks one new question.

▸Technology choices

Choice Justification
One module for tier + requirement explain and the merge verdict read the same code, so they cannot disagree
Commit trailers for provenance Durable, readable with git log, needs no GitHub to audit later — the digest's input
Stdlib only (fnmatch, json, tomllib) Same as every other scripts/ file
